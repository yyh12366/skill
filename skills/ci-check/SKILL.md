# CI 检查

用户要求执行 CI、统一验证或 push 时进入本技能，普通代码实现不自动触发。负责检查与结果汇总，业务代码修复交回实现阶段。用户要求 push 时先完成验证，通过后再继续已授权的推送；失败或阻塞时停止推送。

默认检查用户本批累计改动，检查级别以用户明确要求和项目规则为先，否则按改动自动选择，无须再让用户选择检查级别：

- 仅文档、注释或格式变化：执行适用的文件与 diff 检查。
- 不影响接口或服务运行行为的局部小改：基础检查，仅验证受影响行为。
- 接口、鉴权、持久化或服务启动行为变化：完整检查，包含基础检查和启动服务后的接口实测。

复用代码版本、输入、环境和覆盖范围仍适用的通过结果。必要验证完成后即停止检查；只有失败、后续代码变化或未解决的疑点才补跑受影响项。用户明确只要基础检查时，记录未执行的接口验证。

## 确认范围

- 读取适用的 AGENTS.md，结合 git status、暂存与未暂存 diff、相关新文件确定本批累计范围，覆盖多个需求的全部相关改动，保留用户无关改动。
- 用户给定基准提交或文件范围时按其要求执行；否则检查本批未提交的全部相关变更。无法确认本批边界时询问基准或范围，继续可独立完成的检查。
- 从项目配置、现有脚本和文档确定检查命令、启动入口、就绪信号、受影响接口及预期行为。
- 确认本次已授权的测试修改范围。测试文件的暂存和提交遵循用户指示和项目规则。

## 测试取舍

在本批受影响行为内应用以下原则，不自动扩大为全仓测试治理：

- 从需求、公开契约或真实故障确定预期；当前实现及其生成的输出不能单独证明正确，避免代码和测试共享同一个错误假设。
- 判断测试能抓住哪种具体错误、是否误拦等价重构，以及已有测试或类型检查是否已提供同一保护。优先复用有效用例；机械改动或已有充分覆盖时不强制新增测试。
- 已授权补测或优化测试时，在能暴露真实故障的最低成本层级新增或调整用例，保留必要的真实集成路径。修复用例应尽可能证明原错误会失败、修复后会通过；无法复现时记录缺口。
- 合并、删除测试或放宽断言前，确认剩余用例仍能发现原错误，并允许合法替代结果通过。相似名称、覆盖率重叠不能证明重复；证据不足时保留并报告建议，不通过刷新快照、重试或放宽阈值掩盖失败。
- 数据完整性、权限、兼容性、资源清理和故障恢复的有效保护必须保留；执行慢时先调查准备、执行及清理成本，按证据优化。

判断原则参考 [Test Value](https://github.com/tt-a1i/test-value/blob/main/SKILL.md)，已合并到本技能，无需额外安装或调用。

## 基础检查

- 执行受影响文件必要的语法检查，以及项目已有且适用的 lint、类型检查。
- 执行 git diff --check 和 git diff --cached --check。
- 运行相关测试；公共逻辑影响多个模块、项目明确要求或用户要求时，再跑全量测试。
- 核对筛选命中、实际执行和跳过情况。没有执行相关用例的成功退出不能算行为通过；确实没有相关测试时，说明依据和验证缺口。
- 沿用项目已有工具。缺少工具、配置或依赖时，明确列为未执行或阻塞，不能记为通过。

## 启动与接口实测

完整检查使用项目文档或配置中声明的服务启动入口。保留入口脚本及其参数。

1. 确认测试环境、已授权的测试账号和真实请求输入。缺少必要信息时只询问缺项，并继续不依赖它的检查。涉及数据写入时使用约定的测试数据，清理仅限本次创建且可安全删除的数据。
2. 记录本次启动的进程、工作区、端口和日志位置。设置启动等待与请求超时，以就绪响应和日志判断服务可用；仅有进程存活不能算启动成功。
3. 已有服务可复用时，先确认它属于当前工作区并运行本次代码。端口占用且无法确认归属时报告阻塞，保留其他服务。
4. 使用实际 HTTP 请求，验证修改接口及必要上下游流程的正常行为、关键异常分支和鉴权。按需求检查 HTTP 状态、业务返回码、响应字段与必要的数据变化；通过后续接口或测试环境只读查询核对持久化结果。
5. 接口实测以真实运行服务的响应为证据，不能用 Mock、测试客户端或猜测的结果代替。日志与报告隐去凭据、令牌和个人信息。
6. 成功、失败或中断时，都清理本次启动的服务及子进程；复用的服务保持运行。无法完成清理时报告剩余进程信息。

缺少可运行入口、账号、真实输入或外部依赖时，报告未验证原因。检查本身不新建接口、不重写启动脚本，也不执行发布部署。

## 输出

简要列出：

- 本批覆盖的变更范围、实际执行的检查命令与通过或失败结果。
- 测试取舍依据、复用的结果及覆盖缺口；若已授权修改测试，说明保留了哪些保护。声称提速时给出可比条件下的实测数据。
- 启动方式，以及服务是否对应当前工作区和代码。
- 实测接口、关键断言和结果，避免披露敏感数据。
- 未执行项、阻塞原因与服务清理结果。

代码或接口断言失败记为检查失败；环境不足记为阻塞或未验证。只有要求的检查全部完成，才报告完整检查通过。
