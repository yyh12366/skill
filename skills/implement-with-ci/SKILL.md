# 实现，最后统一 CI

直接调用本技能即选择此流程，无须再次选择。支持连续完成多个需求，CI 由用户要求统一验证或 push 时触发。

## 实现

读取适用的 AGENTS.md、需求、相关代码及调用方，按现有结构完成必要修改，保留运行时校验和错误处理。

默认只实现和审查代码，不自动新增或运行测试、执行 CI 或启动服务。用户明确要求本次调试、测试或验证时，按其要求执行，并保留结果供后续 CI 复用。

## 审查与暂存

审查本次 diff 的需求覆盖、正确性、性能和项目规范。代码审查在本阶段完成，运行验证留给用户触发的独立 CI。

按用户指示和项目规则暂存相关文件。默认止于 `git add`，提交、推送和部署按用户授权执行。

简要报告本轮修改及待验证行为，明确标记“未执行 CI，待本批改动统一验证”，不能将代码已修改或已暂存表述为验证通过。

## 独立 CI 入口

用户要求“跑 CI”“统一验证这批改动”、push 或调用 ci-check 时，读取并调用 [ci-check](../ci-check/SKILL.md)。如果相邻目录下没有该文件，按名称查找已安装的 `ci-check`。传入本批累计变更范围、需求、已有检查结果和已知测试环境。验证覆盖本批全部相关改动。

测试取舍统一遵循 ci-check 中的原则，在授权的验证阶段审视保护、复用结果并执行必要检查。用户要求 push 时，先验证通过再继续已授权的推送；失败或阻塞时停止推送。

不按改动数量自动触发 CI，也不在每轮实现结束后要求用户决定是否测试。
